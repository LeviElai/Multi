# Daily Quest and mobile gameplay release — 26 October 2026

## Changes
- Shared active-game viewport uses visualViewport, safe areas and compact controls. Preserves existing illustrations and palettes. Claw decoration no longer intercepts answer taps; circular projectiles use a stepped pixel sprite with fixed proportions.
- Fishing single-catch-v2: one committed answer and timing attempt, correct in-zone catch earns 500–1,000; wrong/miss earns zero. Existing catch-v1 sessions retain their original rules.
- Stack support-v1: contact intervals and cumulative centre of mass reject unsupported towers. Only valid denominations and a matching total are accepted by the server. Invalid placements fall; successful seal has explicit feedback. This is a lightweight support model, not a full rigid-body physics engine.
- New sessions opt into rules version 2 when GAME_RULES_V2=1. That version is persisted atomically in the creation event, protecting existing room and published-quiz history.
- Time scoring: base successful performance × (1 − 0.5 × elapsed/duration), rounded, clamped. Estimate/Size/Count and proximity scoring instead use 0.2, preserving accuracy dominance. Fish and Crack already calculate their own timing and are not multiplied twice. Crack retains unlimited guesses, 0.8^wrong-attempt decay and its existing 15% timing adjustment. Timing uses server receipts and persisted pause segments. No client score or timestamp is trusted.
- Daily Quest homepage entrance, countdown, ten timed questions, score/rank reveal, podium, sharing and permanent date archive. Official one-attempt uniqueness is transactional. Practice cannot replace official rankings. Answers remain private until committed; revision compare-and-swap and receipt keys prevent duplicate scoring.
- Daily score: correct × round(1000 × (1 − 0.5 × elapsed/20000)); late/incorrect=0. Ties use score, correct count, cumulative server response milliseconds; identical values share rank. Rows have stable owner ordering.
- Reviewed source inventory and AI selection of approved IDs, deterministic fallback and answer shuffling. AI cannot invent publication facts. The launch pool is limited (34 questions), not an unlimited fact-verification system.
- Session restoration state machine, deduplicated identity checks and retry without cookie deletion on transport failures. Daily sign-in returns to the challenge. Safe lifecycle logs record status and duration only.

## Authentication finding
The application uses custom seven-day HttpOnly cookies, not Supabase refresh tokens. The old creator gate depended on the profile/quota endpoint. The new gate uses the narrower identity endpoint and explicitly separates transient failures, anonymous and expired states. Local persisted-context and outage tests reproduce recovery behavior; the reported hours/days-later production failure has not been conclusively reproduced. Do not label its complete root cause confirmed.

## Security verification
- Upgraded Next 16.3.4 to 16.4.1, Zod to 4.6.6 and affected transitive dependencies. `pnpm audit --prod` reports zero advisories after the changes. This is not a claim of complete security.
- New daily tables use backend ownership, RLS and no anon/authenticated grants. Publication has a fixed search_path and narrowly scoped function, executable by the scheduler role. Published questions are immutable.
- Existing lifecycle coverage checks authorization, forged identity headers, invalid origins, host impersonation, scoped player/display tokens, duplicate receipts and process recovery. Daily tests check ownership, concurrent attempts, score forgery surface, repeat answers and historical practice isolation.
- Frontend adds framing, MIME, referrer and permissions headers. CSP restricts objects/base/framing; a strict nonce-based script policy remains future work.
- No claim of a complete ASVS audit, penetration test, physical-device validation or abuse-proof identity. Email verification, external lookup and multi-account cheating remain limitations.
