# 25 October follow-up: authentication and Crack

Continues from `80f7d359`. Not a completed product overhaul or production release.

## Implemented

- Sign-in verifies the resulting session identity with `/api/auth/me` before navigating. Missing cookies or an inconsistent identity produce an actionable error rather than a redirect loop. A synchronous submission guard prevents double POSTs; login/register tabs cannot change during a request.
- Creator return destinations are constrained to local creator/host/account routes, excluding login and API loops. Expired host sessions redirect back through sign-in with their destination retained.
- The client API rejects malformed HTTP-200 envelopes rather than treating them as a signed-out profile. An external abort signal no longer disables the 15-second timeout. Existing HttpOnly/Secure/SameSite cookie protections and backend Origin checks are unchanged.
- New Crack rounds use `deduction-v1`; already-published rounds without that setting keep their previous rules. Players can keep guessing until solved or time expires. Each wrong guess multiplies the next score by 0.8; the time multiplier is 0.85 + 0.15 × bounded remaining-time fraction. Correct answers earn at least one point; incorrect answers earn zero.
- Crack guesses have a server-enforced 750 ms interval. Consecutive duplicate values are rejected without consuming an attempt. Idempotent replays return the original receipt. Attempt counts and awarded points persist server-side across restart. Client-provided score fields are rejected.
- The new compact Crack form provides numeric keyboard entry, higher/lower feedback, attempt count and remaining potential points. Practice uses the same deduction calculation. The live round timer remains visible in the shared round header.

## Evidence and limits

Production GET `/api/v1/features`, `/api/auth/me` and `/api/v1/me` returned HTTP 200. Synthetic invalid login POSTs returned expected 401 `INVALID_CREDENTIALS` on both public Vercel aliases. These checks did **not** reproduce the reported successful-login failure and are not evidence that authenticated mobile login is fixed.

Added regression tests for missing/mismatched browser session identity, malformed responses, unsafe/looping return destinations and Crack's thirteen-guess solve, cooldown, duplicate requests, server restart, private player projection and anti-forgery. A scoring bug caught by the new integration test was fixed: revalidation must preserve trusted engine-written deduction metadata while still rejecting it from client input.

189 unit/integration tests and all four service lifecycle tests passed. TypeScript and a Next.js webpack build passed. The existing service lifecycle suite retains the legacy Crack scoring fixture explicitly; the new policy has clock-controlled integration coverage.

Desktop Chrome played the deployed preview at commit `e214536906e29a04651c6e1868257608e806a28a`: guesses 1900 and 1950 returned higher/lower clues, then 1945 solved the practice round for 606 points. The final podium and standings both showed 606. Two opponents were explicitly simulated; this was not independent-client multiplayer testing. Browser inspection caught obsolete digit-wheel instructions in the intro and world cue; those have been corrected. Mobile Safari, Android touch behavior, successful account login and live browser multiplayer remain unverified.

Research used: OWASP Session Management Cheat Sheet (https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), and Jackbox's browser/room-code joining guidance (https://support.jackboxgames.com/hc/en-us/articles/15794759479959-How-do-I-join-a-game). Session identity remains in HttpOnly cookies; guest joining remains separate from creator authentication. No claim of subjective enjoyment follows from automated test results.
